# 06 P1–P5 实施计划

原则：**每一阶段只有一个新增风险，且该风险必须在进入下一阶段前被可复现的证据关闭。** 资金规模不随阶段自动放大——放大是独立决定。

资金基线：29.30 USDT。单笔**目标 5.00 / 硬上限 5.05** USDT、单笔风险 0.30 USDT、累计亏损 1.50 USDT 熔断，P1–P5 全程不变。

---

## P1 — 只读闭环（不碰钱）

**新增风险**：无。全部只读。

**交付**

| 件 | 内容 |
| --- | --- |
| `src/market/snapshot.py` | `/api/v3/exchangeInfo` + `/ticker/24hr` → 归一化 `Snapshot`；含 24h `quoteVolume` 深浅判定（见 [04 §二](04-venue-audit.md)） |
| `src/wallet/readonly.py` | 基于 `READ_ONLY_PATHS` 的签名只读，返回结构化账户对象；不含任何下单方法 |
| `src/ledger/jsonl.py` | append-only 写入 + 读取；每行含 `ts/kind/payload/prev_hash` |
| `src/reporting/daily.py` | 从 ledger 生成日报（Markdown） |
| **`tools/clock_guard.py`** | 连续采样时钟偏差，中位数 > 1000 ms 即拒绝进入 live（闭合 R2） |
| `tools/capture_filters.py` | 把 `exchangeInfo` 快照落盘并按 R6 做字段契约断言（字段消失即 CI 红） |
| CI | `python -m unittest` + 一条"能拉到 3 条标的过滤器且量化可行"的 smoke |

**验收门（全部满足才进 P2）**

1. 连续 24 小时、每 5 分钟一次快照，成功率 ≥ 99%，失败样本有原因分类（含 429/418 限流分类）；
2. **时钟偏差**：24 小时采样中位数的绝对值 < 200 ms，且**无一次**超过 1000 ms（当前实测已出现 −2,762 ms，见 [04 §一](04-venue-audit.md)）；
3. 账本可回放：从 P1 首日到末日的所有快照能重建成同一份日报；
4. **API Key 已就绪**：`tools/account_probe.py` 退出码 0（`canWithdraw=False` + 权限 ⊆ SPOT），闭合 [03](03-holdings-snapshot.md)；
5. `exchangeInfo` 契约测试连续 7 天通过（字段 `LOT_SIZE.stepSize` / `NOTIONAL.minNotional` 均未消失）。

**禁止**：任何下单（此时 `[execution] enabled=false`，且测试网也尚未启用）；任何持仓声明（账本是空仓，因为确实没交易）。

---

## P2 — 影子账本 + 回测（仍然不碰钱）

**新增风险**：模型过拟合被当成能力。

**交付**

- `src/paper/`：用观测到的盘口/成交价做影子成交，含滑点与手续费扣减（**无 gas**，CEX 不收 gas）；
- `src/backtest/`：kline 回放，产出 equity curve、最大回撤、样本外区间；
- `src/ledger/`：paper 与 live 用 `mode` 字段隔离，禁止混算。

**验收门**

1. 影子账本跑满 100 笔虚拟成交，账目自洽（equity 变化 = 已实现盈亏 − 手续费，误差 0）；
2. 回测的样本外区间与样本内表现差距 < 50%（否则视为过拟合，策略不得进 P3）；
3. 影子结果与 `risk.assess` 联动：被风控拒掉的意图必须记账为 rejected，不得静默丢弃；
4. **回测必须按真实约束算**：单笔目标 5.00 / 硬上限 5.05、最多 1 仓、本金 29.30 → 单笔利用率 ≤17%。用 29.30 全额回测的结果一律作废（[07 R4](07-risks-and-blockers.md)）。

**禁止**：用回测收益宣称预期收益；任何真实下单调用。

---

## P3 — 极小金额实盘（第一次碰钱）

**新增风险**：真实滑点、真实失败、真实资金损失。

**交付**

- `src/execution/binance_spot.py`：`POST /api/v3/order` 的唯一调用点，强制经过 `assess` + `execution_gate`（P0 已有骨架，`submit_order()` 至今未被调用过）；
- **测试网优先**：先在 `testnet.binance.vision` 跑通全链路，主网要再过 `allow_mainnet=true` 这一道；
- 四道开关的**单笔演练流程**（文档 + 脚本）：改 `enabled=true` → 改 `dry_run=false` → 临时设 `TRADER_LIVE_ORDERS=1` → 执行 → **立即全部复位**；
- 成交回报对账：`/api/v3/myTrades` 与 ledger 逐笔核对。

**资金闸**

- 测试网阶段：无金额限制（假钱）。
- 主网阶段：**目标 5.00 USDT / 硬上限 5.05**（D6 已定，原 ≤2 USDT 与交易所下限 5 冲突，已作废）。
- ⚠️ 由此产生的硬约束：**只有 CAKEUSDT 能成交**——BTC/BNB 的名义步长（0.70 / 0.77 USDT）比整个允许窗口（0.05）还宽。这是 [07 R14](07-risks-and-blockers.md)，P3 若只做 CAKE，等于把全部策略押在 24h 成交额仅 1.5 M 的薄标的上。D7 需要在 P3 之前定。

**验收门**

1. 测试网 20 笔成交全部成功或**可解释地失败**，无"状态未知"；
2. 每笔的实际滑点与事前估算偏差 < 100%（即估算不产生方向性系统错误）；
3. 实际手续费率与 policy 的 `max_fee_bps` 一致（偏差即回写 policy）；
4. 完成一次**故意触发熔断**的演练：把 `realized_loss` 置为 1.50，确认后续意图全被拒；
5. **时钟门**：连续 7 天偏差绝对值 < 200 ms 才允许打主网。

**禁止**：P3 期间调整 `max_notional` / `max_cumulative_loss`；禁止市价以外的订单类型（限价单引入挂单状态机，另立阶段）；禁止任何杠杆/合约/提币路径。

## P4 — 策略上线（AI 决策）

**新增风险**：模型幻觉、提示词注入、过拟合策略在真实资金上失效。

**交付**

- `src/strategy/`：至少两个互相独立的基线（如趋势跟随 + 均值回归），可做 A/B；
- 决策日志：每次 Signal 记录输入快照哈希、理由、被拒原因；
- 策略权限收口：策略拿不到 policy 数值（见 [05 §三](05-architecture.md)）。

**验收门**

1. 连续 14 天，策略决策 100% 可追溯到具体快照（无"拍脑袋"决策）；
2. 对抗测试：注入式快照 / 伪造价格 / 异常 JSON 喂给策略，确认不产生超限意图（风控仍应拦住，但策略不应主动产出）；
3. 策略单日最大亏损不超过 0.30 USDT（单笔风险预算）。

**禁止**：策略自行决定加仓倍数；策略调用 `execution`。

---

## P5 — 复盘与边界重估

**新增风险**：把运气解释成能力。

**交付**

- 全周期审计报告：每一笔成交、每一次拒单、每一次熔断；
- 三份独立结论：数据通路是否稳定、风控是否被绕过、策略是否有边际；
- **边界重估提案**：是否提高本金 / 是否放宽单笔上限 / 是否引入新标的。三者都得由人签字，不由系统自行生效。

**验收门**

1. ledger 与链上 `portfolio` 对账零差异；
2. 存在至少一次"策略想下、风控拒了"的记录，且拒得对（复核确认）；
3. 明确写出「这套系统在什么条件下会亏完 29.30 USDT」，不含糊。

## 阶段依赖与总门槛

```
P0 ✅ ──► P1 ──► P2 ──► P3 ──► P4 ──► P5
                    （P1 的钱包绑定是全局硬阻塞）
```

| 全局硬门槛 | 不满足则 |
| --- | --- |
| 钱包绑定 + 地址人工核对 | **不得进入 P3** |
| 21 条风控测试全绿 | 不得进入 P3 |
| 任一阶段验收门未过 | 不得进入下一阶段，**不得以"先跑起来再说"跳过** |

## 与 D:\ops 侧四个 ADR 的关系

本仓库的 P1–P5 是**新系统**的计划。`D:\ops` 侧已有四条 ADR（不在本仓库，故此处只按题名引用，不做链接）：

- `ADR-0002 交易工作台边界`——独立于只读研究呈现层、首版不接私有交易 API
- `ADR-0003 首版市场与模拟范围`——首版策略、页面与验收范围
- `ADR-0004 验收门分层`——新验收门只对新版本生效、两门并列、W 不进 α 分母
- `ADR-0005 IP 封禁作为保护模式触发源`——418 作为保护模式一等触发源、按 IP 做全局预算

那四条约束的是 `binance-spot-quant`（CEX 现货，首版不接私有交易 API）。本项目是**链上 DEX 且最终要碰真钱**，与"首版不接私有 API"不同源，因此不能直接复用其边界。**相同的是方法论**：验收门只对新版本生效、两门并列、失败不得降级为通过。P1–P5 的每一道门都按这个口径写。
