# ADR-0001：钱包层由 GMGN 托管，本地永不接触私钥

- 状态：**已被取代（Superseded by [ADR-0002](0002-binance-spot-as-venue.md)，2026-11-03）**
  —— 交易场所改为 Binance 现货后，本 ADR 的托管模型不再适用；但其两条结论仍有效并保留（「本地不持有私钥」与「单一 price 字段不可作为定价依据」）。本文保留作为决策沿革，不删除。
- 日期：2026-11-03
- 决策者：项目所有者
- 相关：[02 钱包权限审计](../02-wallet-audit.md)、[05 架构](../05-architecture.md)、[07 R1/R3](../07-risks-and-blockers.md)

## 背景

P0 任务书假设「已有 Binance Agentic Wallet 工作台」，并要求在该前提下审计钱包权限。

实测否定了这个前提（[01 §五](../01-environment-audit.md)）：

- 技能库 14 个 `gmgn-*`，**0 个** `binance` / `agentic` / `wallet` 相关技能；
- 无 `~/.binance` 配置；
- 环境变量无任何钱包/私钥/RPC 相关项。

同时另一条通路是通的：`gmgn-cli` 1.6.2 已装、GMGN API Key 已配、BSC 行情与 gas 都能查。

于是问题从"审计 Agentic Wallet 的权限"变成"钱包层由谁承担"。

## 选项

| 选项 | 说明 | 致命问题 |
| --- | --- | --- |
| A. 自己保管私钥（本地 keystore / 硬件签名） | 本地生成并持有私钥，自行编码 raw tx | 需要私钥进入 AI 可触及的进程边界；AI 被注入或被幻觉驱动时可直接签名。与任务书「禁止把钱包私钥交给 DSH Worker」直接冲突 |
| B. 浏览器钱包 + 人工点确认 | MetaMask 类，每笔人工批准 | 无法自动化（P4 目标是自主决策），且自动化 = 绕过确认 = 回到问题 A |
| C. **GMGN 托管钱包（API Key 绑定）** | 钱包在服务端，本地只持 API Key，通过 `gmgn-cli` 调用 | 信任托管方；API Key 成为单点（见后果 2） |
| D. 不接真钱，只做 paper | 永远不落链 | 无法满足任务书「最终自动执行交易」的目标 |

## 决定

**采用 C。** 本地不生成、不存储、不接触私钥或助记词；`src/wallet/` 只有读方法，本仓库不含任何签名代码。

## 依据（可验证的事实，不是偏好）

1. `gmgn-cli swap --from <address>` 的帮助文本明写 **"must match API Key binding"** —— 钱包与 Key 的绑定关系在服务端，本地拿不到签名材料。
2. `gmgn-cli portfolio info` 的语义是 **"Get wallets... bound to the API Key"** —— 同上。
3. `gmgn-cli swap --yes` 的帮助文本明写 **"requires GMGN_ALLOW_AUTOMATED_TRADES=1"** —— 托管方自带一道自动化闸门，正好可以当第三道开关。
4. 任务书 §2 的三条禁令（不读私钥、不把私钥交给 Worker、不提币转账）在 C 下**结构性地自然满足**，不需要靠纪律维持。

## 后果

### 收益

- **「AI 被诱导签名」这一类风险面消失**：本进程没有签名能力可诱导。
- 任务书三条私钥禁令从"要遵守"变成"做不到违反"。
- 不需要 keystore 加密、助记词备份、硬件钱包集成——P1–P5 少一整块。

### 代价（必须写清楚）

1. **信任转移**：安全性从"代码写得多好"变成"GMGN 靠不靠得住 + Key 保管得多好"。托管方作恶、跑路、被攻破，本地代码一行都缓解不了。
2. **⚠️ API Key 成为单点（新增最高风险 R1）**：Key 泄漏 = 绑定钱包被直接动用，本地没有第二道签名门槛。这比"私钥泄漏"的门槛更低——私钥至少还有本地加密与物理隔离。
3. **白名单与额度只约束"我们发起的"交易**：钱包若在别处被使用，本地 `config/risk_policy.toml` 完全管不到（R3）。
4. **`allowance` 实际额度不可控**：本地只能拒绝"无限授权"的**意图**，控制不了托管方实际签出的链上 approve（[02 §三.7](../02-wallet-audit.md)）。
5. **接口耦合**：`gmgn-cli` 的子命令、字段、语义变化即我等的变化。必须版本钉死并做契约测试（R2）。

### 触发重估的条件

出现以下任一，本 ADR 必须重新评审：

- GMGN 支持把签名权下放到本地（那就回到选项 A 的风险评估）；
- 实验资金规模超过 29.30 USDT（托管单点风险的绝对损失随之上升）；
- 出现一次不可解释的差额对账（怀疑托管方或接口）；
- 绑定钱包被非本项目来源动用过。

## 备选方案为何不选（留档）

- **A（自持私钥）**：与任务书 §2「禁止把钱包私钥交给 DSH Worker」直接矛盾，且要把签名能力放进 AI 可触及的边界。若未来必须自持，最低要求是签名在独立进程 + 硬件隔离 + 人工二次确认，那是另一个 ADR 的工作量。
- **B（浏览器钱包人工确认）**：与 P4「AI 自主决策执行」目标冲突。
- **D（只做 paper）**：不满足项目最终目标。但 P2 的 paper 阶段仍然照做——它是 P3 的前置，不是替代。
